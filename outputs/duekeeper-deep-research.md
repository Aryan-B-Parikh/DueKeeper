# DueKeeper — Deep Research (duekeeper-deep-research) — Cited

**Slug:** `duekeeper-deep-research` · **Date:** 2026-08-25 · **Plan:** `outputs/.plans/duekeeper-deep-research.md` · **Research:** `outputs/.drafts/duekeeper-deep-research-research-direct.md`  
**Mode:** Direct (lead-owned) — no researcher subagents (scale decision, `outputs/.plans/duekeeper-deep-research.md:Scale Decision`)

## Executive Summary

DueKeeper is a self-contained deadline platform (exams, submissions, hackathons, calendar/email extraction, crash-safe reminders) that was audited on 2026-08-24 across 53 TypeScript server files (~7k lines) and rated 6.8/10 [AUDIT.md:1-3][README.md:3]. The audit described a clean vertical slice, parameterized SQL, and deliberate security posture, losing points for one completely broken cryptographic implementation (web push), unwired reliability primitives in the reminder pipeline, and a gap between intended vs verified validation [AUDIT.md:1-10]. Remediation dated 2026-08-25 claims every critical (C1–C4), high (H1–H8), medium §5, and 17-step §8 plan item is closed, with residual risks accepted (single-instance SQLite, scrypt cost, vector-only push, header-only inbox, ticket window) [AUDIT.md:9][AUDIT.md §9]. The working tree as re-verified on 2026-08-25 shows those closures are materially present in code and covered by 129 tests across 33 suites (previously 66 unit-only, one certifying the C1 bug) [AUDIT.md §9][server/src/tests/push.test.ts:14-31][bash: `cd server && npm test` 129/33/0]. Two transient test-environment defects (Google env leakage + redirect URI mismatch) were the only blockers until a small env/test isolation fix (`server/.env:30`, `server/src/tests/http.test.ts:580-665`). No external benchmark was reproduced; performance numbers remain unverified (`README.md:49` `scripts/bench.mjs` not run, `web_search` not exposed).

## Findings by Question / Theme

### 1. What does DueKeeper claim to do vs what the codebase actually does?

**Claimed (README/AUDIT):** Full-stack deadline & reminder platform: canonical UTC `dueAt` + IANA `timezone`, live status `upcoming→due_soon→overdue` plus `done/cancelled` with snooze, heuristic + Gemini extraction (text/screenshot), per-user `deadline+<token>@domain` forwarding webhook (SendGrid-compatible) with auto-save, calendar ICS import/export + optional Google OAuth incremental sync, transactional outbox on SQLite (planner→deliveries→outbox with leases/backoff/watchdog), SSE with ticket, web-push VAPID+RFC 8291, two channels (in-app + SMTP), hardened auth (HS256 JWT, scrypt, revolving refresh with theft detection, rate limits) [README.md:3-5][README.md Highlights][AUDIT.md §1-§2].

**Observed:** All claims are implemented in the expected modules: `server/src/modules/events` CRUD + reminders + status compute [server/src/modules/events/events.service.ts:155-185], `server/src/modules/extract` Gemini + heuristic + `imageValidate` magic-byte check [server/src/modules/extract/imageValidate.ts:9-24][server/src/modules/extract/gemini.ts:25-55], `server/src/modules/inbox` header-only token + `To`-only resolution + timezone-aware extraction [server/src/modules/inbox/inbox.routes.ts:77-115], `server/src/modules/calendar` ICS + Google (`syncToken`, keyword filter, `external_events` identity map) [server/src/modules/calendar/calendar.routes.ts:307-354], `server/src/engine` planner/outbox/scheduling + `server/src/lib` JWT/password/secretbox/push/zonedTime [server/src/engine/planner.ts:99,164][server/src/engine/outbox.ts:96-126][server/src/lib/push/webpush.ts:22-62][server/src/lib/password.ts:1-30]. The single most important original finding (web push never delivered readable payload, metrics said healthy) [AUDIT.md §1] is now inverted: the key schedule is literal and the test suite would fail if it regressed [server/src/lib/push/webpush.ts:50-53][server/src/tests/push.test.ts:14-31][AUDIT.md §9 C1]. No claim of “zero external infra to boot” is violated — the server still boots with `DB_PATH` default and console email fallback in dev [server/src/config/env.ts:136,152][server/src/engine/channels/emailChannel.ts:66-76].

- Scale: SQLite single-instance remains the deployment reality [server/src/db/database.ts:13-15][AUDIT.md §9].
